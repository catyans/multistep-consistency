# Reproducibility guide

Companion to **Multi-step Consistency Models: A Complete Error Theory and Optimal Step Selection**, NeurIPS 2026.

Authors: Yanshu Wang, Rui Liu, Tong Yang. Peking University.
Contact: yanshuwang@pku.edu.cn.
Peking University provided computational resources. The authors declare no competing interests.

This package contains the archived experimental code and compact records supporting the camera-ready paper. It provides two distinct workflows: checking the recorded results without a GPU, and rerunning the sampling and evaluation pipeline. Checking records is not a new experimental reproduction. No models are retrained.

## Quick offline check

Python 3.10 or later is sufficient; these commands need no additional packages, network access or GPU. Run from this directory:

```bash
python verify_records.py
python -m unittest discover -s tests -v
```

Checks cover all 26 official FID values against their archived metric JSON files, sampling seeds/counts/batch sizes, reported timing records, the LSUN paired-bootstrap conclusion and Table 2 pixel sliced-W2 values. Package file hashes are checked when the manifest is present.

To regenerate the numerical curves in Figure 2 from the archived CSVs:

```bash
python -m pip install matplotlib
python plot_records.py --input-dir records --output outputs/cross_model_step_sweep.png
```

This writes PNG and editable SVG plots. The underlying numbers match the paper; typography may differ. Figure 1 is a conceptual schematic, not experimental data. The four fixed-seed grids in `assets/` are the paper's visual examples. Full sample arrays are not distributed. The grids can be regenerated by the sampling stage (`grids/N1.png`, `N2.png`, `N6.png`, `N20.png` for the primary LSUN run).

## Experiment coverage

| Run | Samples per step | Batch | Seed | Step counts |
| --- | --- | --- | --- | --- |
| `lsun_primary` | 10,000 | 64 | 20260724 | 1, 2, 3, 4, 6, 8, 10, 20 |
| `lsun_replicate` | 5,000 | 64 | 20260725 | 1, 2, 3, 4, 6, 8, 10, 20 |
| `imagenet64` | 10,000 | 128 | 20260726 | 1, 2, 3, 4, 6, 8, 10, 20, 30, 40 |

The complete sweep generates 220,000 images. Generation uses float16 on CUDA; the reported local Jacobian diagnostic uses float32. The historical hardware was NVIDIA H100. Raw generated arrays alone require approximately 24.8 GB, plus references, model weights and feature caches. Sampling currently accumulates a complete step's images in host memory before saving, so allow substantial host RAM. CPU evaluation can be slow. No hardware-independent runtime is promised.

For LSUN, pixel sliced-W2 and the auxiliary PyTorch feature pipeline use 5,000 images, including in the 10,000-image primary run. Official FID uses all generated images and the OpenAI reference statistics. ImageNet auxiliary diagnostics use 10,000 images. The metrics are distinct; the `feature_fid` column must not replace `official_fid`.

## Environment and external assets

Use Linux with a CUDA-enabled PyTorch installation and Python 3.10 or 3.11 for GPU reruns. The requirements files are compatibility constraints, **not a recovered historical environment lockfile**. Resolve and record an environment before a long run:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip freeze > installed-environment.txt
```

Install a matching CUDA PyTorch/torchvision build for your hardware. The historical archive did not preserve exact Python, PyTorch, Diffusers, TensorFlow and CUDA versions; byte-identical samples and exact numerical matches across environments are not guaranteed.

Models:

- [LSUN checkpoint](https://huggingface.co/openai/diffusers-cd_bedroom256_lpips): recorded revision `563e73f9d0efe4841b9e303f1761de90dfad2d77`; the generation runner pins this revision.
- [ImageNet checkpoint](https://huggingface.co/openai/diffusers-cd_imagenet64_lpips): historical revision was not recorded. Supply a reviewed local snapshot with `--model-path` to avoid tracking a moving repository.

Obtain the official reference NPZs yourself after reviewing the applicable data terms; they are not included or downloaded by the planner:

- [LSUN reference](https://openaipublic.blob.core.windows.net/diffusion/jul-2021/ref_batches/lsun/bedroom/VIRTUAL_lsun_bedroom256.npz)
- [ImageNet reference](https://openaipublic.blob.core.windows.net/diffusion/jul-2021/ref_batches/imagenet/64/VIRTUAL_imagenet64_labeled.npz)

Place these in `outputs/data/` with the filenames in `runs.json`, or pass an absolute `--reference /path/to/reference.npz` for each relevant stage. Preserve the embedded reference statistics; a different real-image subset or evaluator changes FID. These URLs come from the archived OpenAI evaluation instructions; availability and data access are external prerequisites.

## Rerun the experiments

The runner prints commands by default. It performs no downloads or computation until you add `--execute`. Workers may download model weights, PyTorch FID weights, or the OpenAI Inception graph when executed.

```bash
python reproduce.py generate --run lsun_primary
python reproduce.py generate --run lsun_primary --execute
python reproduce.py features --run lsun_primary --execute
python reproduce.py bootstrap --run lsun_primary --execute
python reproduce.py pixel --run lsun_primary --execute
```

Repeat with `--run lsun_replicate` and `--run imagenet64`. Use a new `--workdir` for each independent experiment: the runner refuses to overwrite existing final outputs. For a pipeline test, `--steps 1` runs only one **full-size** step count, not a tiny sample run. For a genuinely small GPU smoke test, call the worker directly in a separate directory:

```bash
python eval/generate_npz.py --model openai/diffusers-cd_bedroom256_lpips --revision 563e73f9d0efe4841b9e303f1761de90dfad2d77 --steps 1 --num-samples 8 --batch-size 8 --seed 20260724 --out outputs/smoke/N1.npz --grid-out outputs/smoke/N1.png
```

Do not compare smoke-test FID with the paper. Batch size affects the historical generator scheme (seed plus batch index); changing it changes generated samples even with the same nominal seed. ImageNet class labels are uniformly sampled using a separate deterministic generator. Grids use the first 16 samples, without quality selection; matching seeds across step counts do not guarantee identical image identity.

### Official FID

The TensorFlow OpenAI evaluator is separate from the PyTorch feature diagnostics. Use a separate environment if needed:

```bash
python -m venv .venv-official
source .venv-official/bin/activate
python -m pip install -r requirements-official.txt
CUDA_VISIBLE_DEVICES="" python reproduce.py official --run lsun_primary --execute
```

Repeat for the other runs. This creates reference stats and per-step `official/N*.json`. CPU evaluation avoids competing GPU runtimes but is slower. The bundled MIT-licensed evaluator is the archived OpenAI implementation, not a newly downloaded version. It downloads its Inception graph on first use into its evaluator directory. The original upstream commit was not recorded; the bundled source is hashed in `PROVENANCE.json`.

### Bootstrap and pixel diagnostics

`features` creates caches for `bootstrap`; it uses the archived PyTorch-FID feature extraction path, not the official TensorFlow FID pipeline. Bootstrap uses 64 projected features, sample size 3,000 and 2,000 rounds. Keep the full step list and order to preserve RNG use and the data-dependent comparison baseline. Its intervals are not intervals for official FID.

`pixel` uses area-downsampled RGB at resolutions 16 and 32, 256 directions, and 2,000 direction-bootstrap rounds. These intervals capture direction variation, not full image-sampling uncertainty. It is not the full data-space Wasserstein distance of the theorem. Run both resolutions in their original order for the historical RNG stream.

### Local Jacobian diagnostic

Use the LSUN snapshot at the recorded revision for a revision-pinned rerun:

```bash
python reproduce.py jacobian --run lsun_primary --model-path /absolute/path/to/lsun-snapshot --execute
```

This runs eight timesteps, eight trials, batch size one, four power iterations and relative perturbation 0.001 in float32. `records/jacobian_fp32.json` and `records/jacobian_power_summary.csv` contain the historical outputs. Optional fp16 perturbation sweeps can be run directly using `eval/local_jacobian_power.py --help`. Local gains do not certify a global Lipschitz bound. This worker supports unconditional models only and rejects class-conditioned inputs.

## What this package does not establish

- End-to-end CUDA sampling and TensorFlow FID recomputation remain untested in this release. See [validation status](VALIDATION.md) for test coverage.
- The archived full image batches and feature caches are intentionally excluded to keep this package small. They must be regenerated or independently obtained; result JSONs alone cannot recompute metrics.
- The full original software environment and ImageNet model revision are missing. Recovery of these is needed for a stronger exact-reproduction claim.
- Algorithm 1 is a calibration heuristic, not a certified FID optimizer. This repository covers the reported empirical sweeps and diagnostics; it does not include an end-to-end implementation of Algorithm 1 or a complete fixed-step/selector/exhaustive-search benchmark.
- Training and the CIFAR-10 diagnostic experiments are outside this repository's scope.
- Reported latency is the archived generation-script wall time per image, not a fresh synchronized microbenchmark. It includes work inside the timed sampling/output section and depends on hardware, batching, I/O and software.

## File map and provenance

- `eval/`: eight numerical worker scripts from the experiment archive. Generation adds an optional checkpoint revision; the Jacobian worker adds explicit rejection of unsupported class-conditioned inputs. Numerical algorithms are unchanged.
- `reproduce.py`, `runs.json`: safe command planner and recorded configurations.
- `records/`: camera-ready tables, diagnostics, and sanitized per-step metadata/official metrics.
- `plot_records.py`: archived Figure 2 plotting logic with portable styling and PNG/SVG export.
- `third_party/guided_diffusion/`: archived official evaluator and its original MIT license.
- `PROVENANCE.json`, `SHA256SUMS.json`: source traceability and package integrity. Source names are logical archive identifiers, not paths that must exist on a reader's machine.
- `LICENSE`, `ASSETS.md`: retained source license and external-asset boundaries.

Private absolute paths in exported JSON records were replaced with non-executable archive labels. Numerical values were not changed. Their original SHA-256 hashes are recorded for local provenance checks.
